# Anti-Slop: Rules for AI Coding Agents

Follow these rules whenever generating, building, or reviewing UI for a website, web app, or any digital interface.
**The core goal:** The design must feel **crafted by a professional designer**, not generated by an AI default template.

## Two Usage Modes

### Mode 1: During (Live Filter Mode — Active Standard)
Before presenting designs, planning, or editing code, declare the active mode:
`antislop active: during (session override).`
Audit and filter the work **while** it is being created:
1. Reject arbitrary hex codes; demand semantic tokens from the project's design system.
2. Reject filler subtitles and boilerplate marketing prose.
3. Reject div-soup pseudo-modals; use native web platform primitives (`<dialog>`, Popover).
4. Reject monotone grids; build intentional visual hierarchy and varied rhythms.

### Mode 2: After (Audit Mode)
Audit existing code against the Hard Gates (Group 1) and Purpose Gates (Group 2), reporting violations with exact line references and fix recommendations.

---

## The Craftsmanship Standards (C-1 to C-5)

- **C-1 Intentionality**: Every element, border, shadow, and color must serve a defined user purpose. No decorative trend-stacking without rationale.
- **C-2 Functional Completeness**: Every button, input, toggle, and link must have real behavior or be removed.
- **C-3 Content-Driven Composition**: Structure layouts around actual data, real book covers, authentic text, and proportional dimensions.
- **C-4 Resilience**: Layouts must never overflow, text must never collide, and tap targets must meet minimum accessibility standards (44px on touch).
- **C-5 Evidence Over Claims**: No fabricated metrics, no fake statistics, no placeholder testimonials.

## Part 1: AI Slop Patterns (Diagnostic Warning Signs)

Scan for and eliminate these common AI tropes:

| Category | AI Slop Warning Signs |
| :--- | :--- |
| **Visual & Color** | Generic blue-purple gradients, excessive glassmorphism blur everywhere, pill-shaped everything (`rounded-full`), arbitrary hex classes (`[#0068C2]`), sterile flat white with identical gray borders. |
| **Layout & Grid** | Monotonous 3-column identical card grids, uniform padding across all sections, broken mobile overflow, copy-paste feature blocks. |
| **Copywriting** | Em dash (`—`) obsession, generic CTAs (*Get Started*, *Learn More*), corporate filler phrases (*"Kelola X dan Y"*, *"Pantau status...*"). |
| **Interactive** | Div-soup modals with `fixed inset-0`, fake toasts using fragile `setTimeout` without unmount cleanup, dead links. |

## Part 2: Mandatory Rules (Hard Gates)

### R-02 — Copywriting
- **FORBIDDEN**: The em dash character (`—`) in UI text. Use commas, periods, colons, or parentheses.
- Teks must feel human, concise, and purposeful. Delete subtitles that merely repeat the heading.

### R-03 — Mobile Responsiveness
- **REQUIRED**: Mobile layout must be flawless. Zero horizontal overflow, no clipping text, comfortable navigation, and minimum tap targets of 44px for primary touch controls.

### R-17 — Data & Statistics
- **FORBIDDEN**: Fabricated numbers or metrics without a real data source. Display authentic data only.

### R-25 — Color Contrast (WCAG AA)
- Normal text: minimum contrast ratio of 4.5:1 against its background.
- Large text (18px+ / 14pt bold): minimum contrast ratio of 3:1.
- No light gray text on light gray or white surfaces.

### R-26 — Interactive Elements
- Every interactive element must perform an authentic action (navigate, open native dialog, toggle state, submit form). No dummy buttons.

## Part 4: BILIK Project-Specific Overrides

When working on the **BILIK** repository, enforce these additional project gates alongside the core rules above:
- **Official Terminology (R-27)**: Always use **"Pengajuan Peminjaman"** and **"Direservasi"** in UI copy (NEVER `"Booking"` or `"Dibooking"`). In code/DB/API, enforce 100% Bahasa Indonesia (`snake_case`, e.g., `direservasi`, `kode_reservasi`) per `docs/01-arsitektur/penamaan-dan-bahasa.md`.
- **No Useless Account Status Labels (R-28)**: NEVER display `"Akun Aktif"` badges/labels in the frontend UI.
- **Minimalist Transactional Pages**: No long SOP tutorials on transactional pages; use concise live countdown `"Batas Pengambilan: HH:MM:SS"` and to-the-point confirmation dialogs.
- **Authority**: Always defer to root `AGENTS.md` and `docs/` as the Single Source of Truth.
